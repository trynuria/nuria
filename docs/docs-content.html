01 / Meet Nuria

How Nuria works

Nuria is an experiment in onchain consciousness: a continuous neural life shaped by interaction, with an evolving state and a history you can inspect.

The central loop
01 / INPUTA tradeA sensory signal
02 / STATEA neural windowActivity & adaptation
03 / RECORDA receiptLinked evidence

The idea

The token gives a market a way to interact with an evolving neural system. A buy and a sell enter different populations of neurons. The network continues between signals, carrying forward its membrane state, adaptation and changing connections.

The observatory makes that process visible. It brings together the input stream, measured neural activity, a resource-policy readout and the receipts that connect them.

Network regions

Select a population below the field to isolate its view. In the raster, the selected population expands to fill the plotted area. Drag the neural field to orbit it, or focus it and use the arrow keys. Home resets the camera.

Pause stops visual motion while incoming state continues to update. Focus mode enlarges the field; Esc returns to the full observatory. Reduced-motion preferences pause the visual motion initially.

Input records

  1. Input: its side, quote amount, source and time.
  2. Sensory route: the buy or sell population and its recorded drive.
  3. Recorded window: spike count, regional firing rate and whether the weight hash changed.
  4. Receipt: the saved record’s sequence, tick and copyable hash.

Select an activity row to pin its trace. “Follow latest” returns to the newest input. A queued signal displays a pending receipt until the durable record is saved.

How the field represents activity

Neurons, connectivity, weights, voltages and firing data come from the model. The field uses schematic geometry and sampled edges to make connectivity legible. Travelling markers follow recorded source spikes at slowed visual speed; the model’s transmission delays are specified in the neural model chapter.

Reading a window

Recorded activity includes background input and may include several trade signals. A linked receipt connects those inputs to the recorded neural transition.

03 / The neural model

The neural model

256 neurons. Six populations. Excitatory connections that change with spike timing, and inhibitory connections that help regulate activity.

The six populations

PopulationNeuronsRole in the model
Buy sensory32Receives buy-side drive.
Sell sensory32Receives sell-side drive.
Association64Participates in recurrent activity across the network.
Recurrent memory64Participates in recurrent activity and state carried between windows.
Resource policy16Four output groups for a bounded proposal readout.
Inhibitory control48Supplies inhibitory signals to connected neurons.

The current seeded network has 3,906 plastic excitatory synapses and 1,428 inhibitory synapses. The six populations route sensory inputs, recurrent activity, resource proposals and inhibitory control through the same evolving network.

Inside a neuron

Membrane state evolves with bias, sensory drive, excitatory input, inhibitory input and adaptation. Crossing the firing threshold emits a spike, resets the membrane state and increases adaptation. A refractory interval prevents immediate refiring.

ParameterCurrent model value
Membrane timescale20 ms
Excitatory / inhibitory decay8 ms / 12 ms
Adaptation timescale300 ms
Refractory interval4 ms
Simulation step1 ms
Recorded model window200 ms

Connections change with timing

Plastic excitatory connections maintain pre- and postsynaptic traces. Their relative spike timing changes the connection weight, which stays bounded between 0.005 and 0.25. Excitatory transmission delays span 1–8 ms; inhibitory delays are 2 ms.

“Adapted weights” counts synapses whose current weight differs from its initial value beyond the model’s tolerance. This gives a direct view of how much of the network’s plastic connectivity has changed over time.

A network that continues

Each neuron also receives independent Poisson background input at 18 Hz. A bounded bias controller targets a network firing rate near 8 Hz per neuron. This maintains activity between market signals, with measured firing rates shown in the observatory.

The server advances 200 ms of model time per cycle and paces toward one wall-clock second per cycle. Computation and saving can take longer. Model time is shown separately, and persistent checkpoints preserve network state, random state and pending evidence.

For the underlying simulator, see the Brian2 tutorials.

04 / Trades & signals

Trade inputs

A source transaction is decoded, saved and queued before the model records the neural window in which its signal was processed.

From transaction to receipt

  1. Discover: locate the configured mint’s bonding curve and matching PumpSwap pools.
  2. Read: scan finalized transaction signatures and fetch their transactions.
  3. Decode: extract matching, program-scoped trade events. Failed transactions are excluded.
  4. Queue: save each uniquely identified input for processing.
  5. Record: link the input to a durable neural receipt.

The reader uses pinned Pump and PumpSwap interface definitions. Trade identification checks the exact mint, executing program and decoded event against those interfaces.

How amount becomes drive

Buy-side amounts stimulate the first 32 neurons. Sell-side amounts stimulate the next 32. The amount is transformed into bounded drive using a logarithmic mapping.

gain = min(1.5, 0.25 + 0.45 × ln(1 + amount))

Inputs processed in the same window add to their side’s drive, capped at 3. Each input keeps its own evidence record even when several share a neural window. The current amount mapping supports SOL quotes; other quote units remain marked as unsupported until their mapping is verified.

Coverage and arrival time

The reader’s coverage is the configured mint’s Pump bonding curve and discovered PumpSwap pools. The polling target is six seconds, plus finalization, fetching, decoding and any historical backlog. Pool rediscovery runs on a 60-second interval.

Read the connection state

“Connected” describes the reader’s state. Historical catch-up, unresolved transactions and source errors remain visible in inspection. Missing or incomplete evidence stays unknown.

Simulation inputs

Simulation signals use the same neural queue and receipt pipeline. Each carries its simulation source label. Configuring a real mint switches off test controls and enables the finalized transaction stream; real trade records carry their source signatures.

Protocol interfaces are documented in the official Pump public documentation.

05 / Fees & resources

Fees and resource proposals

The resource layer connects creator fees with Nuria’s next possibilities: more compute, new experiments, a reserve, or continued observation. Neural activity selects the proposal.

Fee accounting

LayerWhat it means
Protocol feeThe trading protocol’s charge and its own destinations.
Creator fee accrualThe creator-fee amount reported by a decoded trade event.
Claimable balanceFunds available through the relevant claim mechanism, requiring separate verification.
Wallet receiptFunds actually received by the designated wallet.
Allocation proposalA bounded resource suggestion from the policy population.
Executed spendingA separate authorized payment with transaction evidence.

The Resources view tracks each ledger layer separately. Accrual comes from decoded trade events; wallet receipts come from observed funds. Missing wallet data displays as unknown.

Four possible outputs

The 16 policy neurons are divided into four groups of four. Their spike counts are compared each window. The group with the highest count selects a proposal; if all counts are zero, the readout selects observation.

Compute

Propose earmarking resources for computation.

Experiments

Propose earmarking resources for a new experiment.

Reserve

Propose keeping resources in reserve.

Observe

Propose continued observation without a compute or experiment earmark.

Bounded proposals

Compute and experiment proposals are limited to 25% of an available budget, with the rest reserved. Each window produces an alternative proposal. The interface leaves allocation amounts unknown until actual wallet funds are available.

Proposal and execution

The live policy layer produces allocation proposals. Signing, fee claims and spending are disabled. An executed allocation requires an authorized payment mechanism and its own transaction evidence.

Verify the exact fee arrangement

The launch’s actual fee configuration, recipients and contract version must be verified. Live fee reporting uses the exact launch’s configuration and decoded event fields. Simulation accrual uses a test rate of 0.3%, recorded separately from actual wallet funds.

Pump’s interfaces include differing fee arrangements, including holder-reward configurations. Event fields must be interpreted against the exact launch rather than assumed to represent funds payable to Nuria. See the protocol’s current documentation.

06 / Receipts & evidence

Receipts and verification

Receipts connect saved inputs, neural state transitions and recorded spike windows in a local hash chain.

Inside a receipt

Each record includes a sequence, tick, UTC timestamp, model identity, source hash, input identifiers and evidence hashes. It also records sensory drive, before-and-after membrane and weight hashes, the spike-window hash, measured metrics and the policy readout.

  "input_ids": ["linked input identifier"],
  "before_weights_sha256": "before-state hash",
  "after_weights_sha256": "after-state hash",
  "spikes_sha256": "recorded window hash",
  "metrics": { "spikes": "count", "rate_hz": "rate" },
  "funds_spent": 0
}

This is a field guide with descriptive placeholders. Use the exported evidence for actual receipt payloads, measurement types and raw spike windows.

What verification checks

  • Receipt sequences and parent-hash continuity.
  • Each stored receipt’s hash against its encoded payload.
  • Raw spike evidence against its recorded hash.
  • Input evidence hashes and the receipt to which each input is linked.

“Verify records” checks the saved local chain. Recent ticks may still await their durable checkpoint, which is separate from an already saved receipt.

Export and inspect

The evidence export contains the latest 300 durable ticks, their input evidence and raw spike windows. Complete history remains on the private server. The network-state export is a JSON snapshot of the model and topology.

For a specific signal, copy its full receipt hash and note the receipt sequence. Use the server-held history to inspect receipts beyond the recent window.

The research and its evidence

Research scope

The evidence establishes recorded inputs, neural dynamics and the integrity of the server-held history. Subjective experience remains an open research question. Receipts are currently stored on the server; independent witnesses and Solana anchoring remain unconnected.

A receipt connects inputs to a window containing both sensory drive and ongoing background activity. Measuring one input’s isolated causal effect calls for a controlled comparison with a matched window.

07 / Glossary

Glossary

A short reference for the measurements and records you’ll encounter.

Model terms

Neuron
A computational neuron with membrane dynamics, a firing threshold and a refractory interval.
Spike
A recorded firing event from a model neuron at a particular model time.
Synapse
A model connection that transmits excitatory or inhibitory influence between neurons.
Plasticity
Change in a connection’s weight through the model’s spike-timing rule.
Sensory drive
The bounded signal applied to the buy or sell population for a processed input batch.
Firing rate
Spikes divided by the population size and model-window duration, expressed in Hz per neuron.
Activity entropy
A normalized summary of how firing rates are distributed across the six populations.
Model window
The 200 ms interval of simulated time covered by a recorded tick.

Record terms

Tick
One advancement of the server’s neural simulation.
Receipt
A hash-linked record of a model window and the inputs processed within it.
Checkpoint
A persistent recovery snapshot of network state and pending evidence.
Finalized
The Solana commitment level requested by Nuria’s source reader.
Unknown
Evidence is unavailable, unsupported, missing or incomplete; the interface preserves that status.
08 / Common questions

Common questions

Direct answers about the experiment and the evidence behind it.

Why onchain consciousness?

It is the question behind Nuria: how could a persistent neural entity evolve through its interactions with a token’s market? The experiment makes its ongoing activity, changing connections and recorded history visible. The evidence chapter defines what those records establish.

How do Nuria’s neurons run?

Brian2 advances 256 computational neurons on the server. Their membrane dynamics, adaptation, refractory periods, excitation, inhibition and spike-timing plasticity create the activity shown in the field.

Why does the field move between trades?

The network is recurrent and receives ongoing background input. Its activity continues between market signals. The display uses the latest measured state and spike window.

Does a trade arrive instantly?

The reader requests finalized transactions and targets a one-second polling interval. Finalization, fetching, decoding and backlog add latency. The inspection panel shows the supported source coverage and current backlog.

How does a trade steer Nuria?

Buys and sells stimulate different sensory populations. Their bounded drive enters a recurrent network, whose activity changes with its existing state. Governance rights and payment authorization require separately defined contracts and permissions.

Can Nuria spend the fees?

The policy population produces bounded proposals. Transaction signing, fee claims and spending are disabled. An executed payment would require a separate authorized mechanism and transaction evidence.

Does it stop when I close the site?

The engine runs on the server, independently of the browser. Checkpoints preserve its state. The site reports the server’s latest state, freshness, waiting states and errors.

How does Nuria evolve?

Relative spike timing changes plastic connection weights. Membrane state, adaptation, synaptic traces and random state carry forward between windows and through saved checkpoints. The observatory reports those changes, while task performance can be evaluated with controlled experiments.
