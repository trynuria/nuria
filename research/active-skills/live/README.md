# Live input-only acquisition and reuse

The running numeric skill route accepts diagnostic inputs without a supplied
program hash, format number or recipe. It requests two distinct audit answers,
tests retained programs against those answers, and uses bounded synthesis when
none fits. One committed program then faces separate buyer-held final rows.
Accepted programs persist; both success and rejection return one delayed outcome
to the originating neural decision and its committed checkpoint.

This is a deployment integration course, separate from the
[frozen external text qualification](../README.md#reserved-result-useful-execution-no-comparative-improvement).
Its numeric observations were already used in development; the repair formats
and arithmetic tasks are generated. It does not measure new customer demand,
neural superiority or broad generalization.

## A course-selection error kept visible

The [initial 32-episode certificate](initial-course.json) checked all 32 outcomes
and their committed neural acknowledgments: 31 acquisitions passed all 620 numeric
final rows; the unsupported SHA256 control abstained and was rejected on its
20 rows. It disclosed 64 diagnostic answers and consumed 32,164 provider units
plus 10,676 buyer-check units, including the rejected work. Its canonical
certificate SHA256 is
`f4b687f46ffbfecc33ce0fe3588136709511cd4450b30b1a3ca5463b4457af44`.

The checker invocation required exactly 32 episodes, at least one acquired
selection and at least one retained selection. This verifier version does not
embed those CLI gate values in the certificate. Its counts and empty `gaps` list
show all 32 outcomes were checked, but zero reused selections leave the
certificate deliberately **incomplete** against the minimum-reuse gate.
The four selected files marked `serve` by the full corpus had recipe identities
that this smaller course had not acquired. They became valid new acquisitions,
not reuse tests. Corpus phase names were insufficient evidence of a recurrence.
This is an operator course-construction error, not an autonomous repair by Nuria.
All initial contracts, outcomes, costs and negative feedback are preserved.

Four appended tests match the actual earlier recipes and use separate source
rows and visible inputs for each matched acquisition. The learner still receives
no recipe, format number or selected program. Recipe metadata protects the
operator's evaluation construction; it does not decide the runtime program.
Two different recurrence formats share one underlying source observation, with
different visible inputs. These are development integration checks, not wholly
new independent data or a rerun of the frozen external qualification.

## Independent checks and limits

The [read-only verifier](../../../scripts/verify_live_active_skills.py) reconstructs
diagnostic exchanges, session bindings, committed selections, delivered artifacts,
independently executed final outputs, admission and charged work. It checks the
full inspected commerce journal, the relevant cognitive records and one durable
acknowledgment per outcome. Current library contents must equal the sequence of
actual checked admissions. An unsupported task must not become a retained skill.

The verifier imports no controller, provider, learner, simulator or signer. It
uses separate read-only WAL views, which are individually consistent rather than
one globally atomic observation. It checks history continuation from immutable
predeployment snapshots. These local commitments are not an external witness or
an onchain attestation. Search internals, physical CPU, every historical cognitive
record and synaptic deltas are not independently replayed; changed-synapse counts
are explicitly recorded counts.

All jobs use included server capacity and zero wallet payment. Financial policy
and external execution remain disabled. Ledger counts are not an independent
wallet balance or transaction-history audit. The finite queue stops proposing
jobs when exhausted; it does not create unlimited work or discover arbitrary
incidents by itself.

The isolated integration and verifier tests cover a Brian2-to-acquisition-to-reuse loop, rejected
outputs, the unsupported SHA256 control, interrupted operations, late deliveries,
source mismatches and missing financial evidence. To inspect the checker and
run its isolated tests:

```sh
python -m scripts.verify_live_active_skills --help
python -m unittest discover -s tests -p test_live_active_skills.py -v
python -m unittest discover -s tests -p test_active_skill_tasks.py -v
python -m unittest discover -s tests -p test_build_active_skill_queue.py -v
```

Running the checker against production requires the protected job journals,
catalogue, controls and baseline snapshots. A public certificate alone does not
let an outside reader reconstruct private inputs or the production database.
