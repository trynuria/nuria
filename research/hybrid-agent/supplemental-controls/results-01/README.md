# Supplemental simple controls

This package completes the originally selected schema-first and stateless
conditions under a separately published, post-hoc protocol. It preserves the
original comparison's 120 selected records and 64 executed records. It is not a
new unseen or independently randomized experiment.

`replay-result.json` reports actual coverage and accepted answers. A condition is
graded only after all twelve agent proposals exist and all supplemental
inference has ended. An incomplete condition retains unknown acceptance. An
accepted count of zero with no graded cases is not a measured zero accuracy.

From a repository checkout whose frozen source hashes match:

```sh
python research/hybrid-agent/supplemental-controls/results-01/verify_results.py \
  --package research/hybrid-agent/supplemental-controls/results-01 --repository . \
  --workspace /path/to/new-private-replay --output /path/to/new-check.json
```

The reader checks every ZIP member and
original hash, reconstructs a new private workspace, replays final queries and
checks canonical reasoning requests, registered tool records, memory chains,
coverage and conservative accounting. No inference, encoder, payment or pickle
loading occurs. Replaying records is not a bit-exact model regeneration claim.

The fixed model, serial condition order, public benchmark exposure and post-hoc
selection limit generalization. Earlier unknown completion use remains a 12,214
token ceiling. The semantic work trial's 3,499 tokens also count against the shared
60,000 additional ceiling. Starting cumulative charge is 186,103; controls cannot
silently renew it. Prompt tokens vary and are measured separately.

The local records reconcile allowance arithmetic and relative elapsed fields.
They do not externally attest the model's weights, reported token use, absolute
UTC deadline, backend cancellation or cross-file wall-clock ordering. No
retrievable outcome settlement or neural credit is applied by these controls.

The archive retains original bytes; `prior-closure.json` is an explicitly derived
view of the three separately pinned original allowance records. The independent
checker receipt is another derived record. Model weights, credentials, host
paths and production histories are excluded.
