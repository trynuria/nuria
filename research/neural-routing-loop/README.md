# Outcome-trained search research

This directory retains exploratory development for an opt-in spiking search
policy. **There is no passed qualification or deployed policy replacement.**
The existing application, recurrent circuit, histories and financial authority
are unchanged by these experiments.

The [latest acquisition study](../../docs/semantic-acquisition.md) recovered
verified programs for 124 of 128 previously failed training jobs. Subsequent
normal-budget spiking performance rose from 316 to 356 accepted jobs out of 384. A stronger same-history field-template control accepted 382, with two
wrong proposals versus one for the spiking controller. **The neural-superiority
interpretation did not survive that control.**

The [implementation notes](../../docs/neural-routing-loop.md) describe the
transactional choice/outcome bridge and its remaining integration gates. The
[development summary](development/summary.json) includes failed budget routing,
fixed search profiles, neural selection and a database-plan feasibility probe.
In the two-profile comparison a conventional rule accepted 355/427 tasks, versus
327/427 for the spiking policy. The negative result remains visible.

## Retained development evidence

- [First archive](development/archive-manifest-01.json): all 64 files from the
  completed budget/profile and SQLite probes, including superseded attempts.
- [Benchmark archive](development/archive-manifest-02.json): parser checks,
  development specifications, source identities and the still-sealed reserved
  benchmark inventory.
- [Semantic search archive](development/archive-manifest-03.json): four
  completed priority-learning variants, full checkpoints and losslessly
  compressed training and delivery traces. The [summary](development/semantic-summary.json)
  retains every negative comparison; the [technical notes](../../docs/semantic-guidance.md)
  explain the mechanism and its limits.
- [Larger curriculum archive](development/archive-manifest-04.json): the
  completed 2,000-task synthetic teacher course, common training records,
  checkpoints, deliveries and strong same-history program-memory control.
  The [curriculum notes](../../docs/semantic-curriculum.md) report the negative
  neural comparison: 319/384 accepted versus 333/384 for the existing solver.
  Retaining whole accepted programs reaches 23/43 external development tasks
  with zero wrong proposals, versus 22/43 with one wrong proposal for every
  main fitted/static controller. This is conventional memory evidence, not a
  neural-specific gain or an unseen qualification.
- [Operation-selection notes](../../docs/semantic-operation-selection.md) and
  [complete summary](development/operation-summary.json): prospective
  operand/family choices with identical observations and grouped prior history.
  The spiking controller accepts 316/384 with two wrong proposals, while the
  existing solver and nearest-neighbor control each accept 333 with one wrong.
  The exact indexed neighbor rerun improves its measured local search CPU while
  preserving shared program/work/outcome fields; it is conventional engineering,
  not neural-superiority evidence.

The [independent delivery replay](development/semantic-independent-deliveries-03.json)
reconstructs 14,592 authored deliveries, acceptance, buyer work and aggregate
arithmetic. It also checks archive identities and private-material screening
inside compressed content. It does not reconstruct search visitation, timing,
gradient updates or external receipt authenticity.

The [operation-selection record](../../docs/semantic-operation-selection.md),
[warm-frontier archive](development/archive-manifest-06.json),
[acquisition archive](development/archive-manifest-07.json) and
[stronger-control archive](development/archive-manifest-08.json) retain the later
experiments. The [exact neighbor index](../../docs/exact-feature-neighbors.md)
is a separately checked conventional optimization; it supplies no neural
advantage or production speed guarantee.

Each manifest distinguishes original byte hashes from published byte hashes.
Absolute local paths, an implementation-ownership annotation and bounded
coordination-only metadata are normalized where indicated. Numerical results
are unchanged. Historical Python scripts are
retained as `.py.txt` snapshots rather than supported executable entry points.
Some inventory snapshots reference historical inputs outside this archive;
these snapshots are evidence, not a claim of one-command full reproduction.

The initial budget attempt omitted common audit charges. The first SQLite
attempt accidentally used redundant join predicates. Their corrected successors
are separately retained; the earlier artifacts must not support an efficiency
claim. Interpreter work, CPU time, accepted deliveries and wrong proposals are
different measurements.

## Upstream data and prior art

The 43 Duet development specifications and derived checks under
`development/eval-design-01/` originate from the pinned Duet source recorded in
the manifests. They retain the upstream [GPL-3.0 license](development/eval-design-01/duet-LICENSE).
The independently written project parser and runtime code are separate from
those benchmark materials. Original constraints, specification-derived checks,
unsupported tasks and unscorable tasks remain distinct.

The 162 reserved specification bodies have not been downloaded or inspected in
this development record. A source/selection freeze and declared evaluation are
required before opening them. Development success cannot substitute for that
test.

Learned prioritization of executed intermediate programs is established prior
art. [BUSTLE](https://github.com/google-research/google-research/tree/master/bustle)
and [its paper](https://arxiv.org/abs/2007.14381) motivate a further experiment;
an independently implemented spiking ranker would not make the general approach
new. Likewise, [Bao](https://arxiv.org/abs/2004.03814) already studies learned
database-plan selection. The SQLite pilot was stopped because a small histogram
rule nearly matched its oracle, leaving little practical neural headroom.
