# Accepted programs, later observations

Four independently accepted model programs were acquired as finite report tools.
Their exact code then ran on actual repository observations captured after their
original acceptance. No new model request was made.

| Method                                        | Accepted | Delivered |
| --------------------------------------------- | -------- | --------- |
| Retained accepted program                     | 4/4      | 4         |
| Independent conventional exact implementation | 4/4      | 4         |
| Stale original answer                         | 0/4      | 0         |

The source snapshot contains 25 pull requests, all 142 commits returned for the
pinned branch head, and 30 recent workflow runs out of 180 reported runs. These
collections differ from those used for acquisition. The component report uses
the historical commit identities from the original enrollment against the newer
Git graph; it makes no new service-health claim.

The profile, implementation, control algorithms and independent oracle functions
were frozen locally before fetching these observations; publication follows
execution. All four jobs and three methods are retained. The ancestry oracle uses
repeated relaxation while the conventional
control uses breadth-first search. The stale-answer arm is a diagnostic, not the
strong simpler comparator. The conventional implementation is that comparator
and ties all four accepted outcomes.

`cases.json` contains complete fresh task inputs, independent checks, file
contracts and every control program. `skills-before-transfer.json` contains exact
acquired programs, accepted origin identities and delivery receipts.
`origin-journal.json` preserves their actual originating records and events.
`retained-courses.json` holds the new work and delivery receipts; rejected control
outcomes remain in `control-records.json`. `artifacts.zip` includes all twelve
programs, actual report files and terminal diagnostics, including stale reports.

Identical retained work replayed all four receipts and delivered bundles with
zero additional executions and byte-identical work journals. The original
acquisition database was also unchanged. Local hashes are consistency evidence,
not an independently authenticated remote witness.

The replay rebuilds the original logical journal, verifies acquisition, executes
all twelve method/job contracts and checks duplicate replay. Use a new workspace;
evidence is retained. The separate native replay reproduced every result.

This is a useful changed-source tool workflow, with a strong conventional tie.
It does not establish general intelligence, neural superiority, unrestricted
skill discovery or production activation. The broader 108-task programming
comparison and its failed superiority gate remain unchanged.
