# Fresh project work and delivery

Four hosted-model jobs ran against fresh Nuria source/API projections and actual
recorded experiment outcomes. **Two passed and delivered artifacts; two failed.**
Every model response and failed host result is retained.

| Job                        | Host result | Actual artifact                                                          |
| -------------------------- | ----------- | ------------------------------------------------------------------------ |
| Proposed source audit      | Accepted    | Complete difference between 1,728 published and 1,760 proposed Git blobs |
| Reported component audit   | Rejected    | No accepted delivery                                                     |
| Reported provider outcomes | Rejected    | No accepted delivery                                                     |
| Reusable experiment audit  | Accepted    | Exact integer paired comparisons and the failed promotion gate           |

The experiment auditor processes different method names and cohorts. Beyond its
108-task source, the host checked the same generated program on the separate
112-task historical course. This is a useful generated computation tool, not a
new model-superiority result.

The component program assumed a commit string was a collection of named records.
The provider report read the wrong utility field and incorrectly marked all
utilities unknown. Their self-checks passed; the independent host checks refused
both. Post-completion checks found their initial programs also failed. Missing
input inspection is an actual interface weakness to fix; another memory layer
is not evidence of a solution.

The complete enrollment was committed in
[eac58cb](https://github.com/trynuria/nuria/commit/eac58cb9f52f8854389a715d6bbe0754911d4f86)
before these model calls. Static retrieval was selected because the broader
comparison gave targeted navigation no checked-outcome advantage. Required file
checks were compiled into host acceptance before inference.

Identical replay returned all four work receipts and both artifact bundles with
zero new model requests, executions or work-journal changes. `replay-proof.json`
records that check. `course-01.json` and `course-02.json` retain the first run and
repeat; `artifacts.zip` preserves exact accepted output bytes and receipts.
`summary.json` gives usage at configured token prices, not a provider invoice.

Public endpoint reports remain distinct from direct service inspection, and no
payment, token trade, signing authority or production activation is represented.
